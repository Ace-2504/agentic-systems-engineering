# AGENTS.md: the schema of my Northbridge mini-wiki

Every agent that ingests, queries or lints this wiki reads this file first. The wiki follows Karpathy's LLM Wiki
pattern: **raw sources** (never edited), **the wiki** (markdown pages the LLM writes and keeps up to date) and
**this schema** (written by me). For every rule below, today is **Monday 26 October 2026**.

## 1. Scope and layers

| Layer | Where | Written by |
|---|---|---|
| Raw sources | `northbridge-docs/01_policies/` and `northbridge-docs/02_procedures/` (50 files: policies, amendments, HR documents, SOPs and their forms) | nobody: never edited |
| The wiki | `wiki/pages/*.md`, `wiki/index.md`, `wiki/restricted/index.md`, `wiki/log.md` | the LLM (ingest, file-back, lint fixes) |
| The schema | `wiki/AGENTS.md` (this file) | me |

The other folders of the dump (manuals, service definitions, master data, e-mails, meetings, release notes) are
**not in this wiki**. A question that needs them is answered "this wiki does not cover it", never with a guess.
A document outside the scope that an in-scope source mentions (a manual such as MAN-PUR-72, a release note, a
service, a meeting) gets **no page**: name it by its code in the text of the page that mentions it, without a link.
The only page types are the eleven in section 2.

## 2. Page types and slug rules

One page per document, entity or topic. The slug is the file name (`pages/<slug>.md`) and the link target.
**Slug rules:** lower case; words joined by `-`; built from the document's or record's own code wherever one
exists, so that every source naming the same thing lands on the same page. A slug given in the prompt's registry
always wins over a new one.

| Type | Slug | One page per | Example |
|---|---|---|---|
| `policy` | the document code | policy or amendment | `pol-pur-001`, `amd-pur-2026-03` |
| `procedure` | the document code | SOP; its forms (NBC-F-…) live on the SOP's page | `sop-pur-002` |
| `screen` | `screen-` + screen code | Ledgerline screen a policy or SOP tells staff to use | `screen-pur-po-01` |
| `error` | `err-` + code | error code a policy or SOP explains | `err-po-0412` |
| `supplier` | `sup-` + supplier code, or `sup-` + name if it has no code | supplier a source discusses | `sup-vc-ein-0042` |
| `item-family` | `items-` + code prefix | family of items a rule applies to | `items-bat` |
| `role` | `role-` + role code | Ledgerline role and its approval limit | `role-pur-mgr` |
| `person` | `user-` + user id (`person-` + name if no id) | person who owns or approves something | `user-dokafor` |
| `data-source` | `data-` + short name | structured file (a spreadsheet) a source points to | `data-supplier-master` |
| `topic` | `topic-` + name | idea that crosses documents (a comparison or synthesis) | `topic-price-tolerance` |
| `answer` | `qa-` + short name | good answer filed back from a query | `qa-direct-order-limit` |

Confidential HR documents get `hr-` slugs (`hr-conf-007`). Do not create a page for something that only appears
as one row of a table; the table's `data-source` page covers it.

## 3. What every page contains

```
---
title, type, slug, summary (one line for the index), audience (staff | hr), sources (raw files),
status (current | superseded | future | mixed), created, updated
---
Lead: 2 to 4 sentences, no heading: what this is and what matters about it today.
Infobox: 3 to 8 key/value lines (code, owner, version, effective date, status ...) where the type has one.
## <the sections required for the type>
## Versions and conflicts      only when sources disagree, are superseded or are not in force yet
## See also                    [[links]] to the closest pages
## References                  generated by the build from the [^rN] keys; never written by hand
```

**Sections per type:**

| Type | Required sections |
|---|---|
| policy | *Clauses* (one `###` per clause, in the policy's own numbering), *Who it applies to* |
| procedure | *Steps* (numbered, in order), *Forms and screens*, *Checks and approvals* |
| screen | *What it is for*, *Fields*, *Messages* |
| error | *Meaning*, *Cause*, *How to fix* |
| supplier | *Record*, *Certificates*, *Rate contracts*, *Notes* |
| item-family | *Items*, *Rules that apply* |
| role / person | *Role and limits*, *Appears in* |
| data-source | *What it holds*, *Columns*, *How to look up a row* |
| topic | one section per aspect, each sentence cited |
| answer | *Question*, *Answer*, *Pages used* |

## 4. Citation format

Every sentence that states a fact ends with a reference key to the raw source it comes from: `[^r3]`, or
`[^r3][^r7]` for two. The build turns the keys into the page's References section, one raw location per key:

```
[^r3]: 01_policies/POL-PUR-001_Purchase_Policy_v4.1.pdf, pp. 1-2, §3. Requests before orders
[^r8]: 01_policies/POL-APR-002 Approval Matrix v3.0.pdf, p. 1, §3. The limits
[^r9]: 02_procedures/<file>, p. <page>, §<section heading>
```

Location: PDF = page and section heading; DOCX = section heading; XLSX = sheet and row key. A citation always
points to a raw source, never to another wiki page. If no source says it, do not write it.

## 5. Links

Link the first mention of every document or entity that has a page: `[[pol-pur-001|Purchase Policy]]`. Link only
to registry slugs or slugs that follow the rules in section 2. Every page must be reachable from `index.md` or
from another page (lint reports orphans). A mention of a document code links to that document's page.

## 6. Versions and conflicts

This dump is full of old, duplicate and not-yet-valid documents. The wiki states which rule applies **today** and
keeps the other one visible, with its date.

1. **In force today wins.** A document applies only if its effective date is on or before 26 Oct 2026. Later
   ("ISSUED, NOT YET IN FORCE", "effective 2027-01-01"): state today's rule first, then "From <date>: <new rule>".
2. **Newer replaces older.** A higher version of the same document code, or an amendment in force, replaces the
   older text. Files in `old/` folders and files whose status is SUPERSEDED are superseded.
3. **Copies are one source.** Byte-identical files (`… v2.3.pdf` and `… v2.3 (1).pdf`) are cited once.
4. Record every case under **Versions and conflicts** as: today's rule | the older or future rule | sources and
   dates | kind (`superseded`, `future_dated`, `contradiction`, `near_duplicate`, `duplicate`,
   `inconsistent_naming`). A superseded or future rule is never written as today's rule.

## 7. Permissions

Files under `01_policies/HR/CONFIDENTIAL/` are for HR only (group NBC-HR-CONF). Their facts go only on pages with
`audience: hr`, which are listed in `restricted/index.md`, never in `index.md`, and never linked from staff pages.
A staff page may say that a confidential HR document exists and who may read it, nothing more.

## 8. Operations

**Ingest** (one source at a time): read the source; decide which pages it touches; add its facts, each with a
quote and its location; record conflicts; append to `log.md`:
`## [<timestamp>] ingest | <file> | +<created> ~<updated> | <slugs>`.

**Query**: read `index.md` first; open the pages whose summaries fit; follow `[[links]]`; open the raw source
when a page points to a table or the exact wording matters; answer with citations to raw sources. Say "not in the
documents" when the wiki's sources do not hold the answer, and "this wiki does not cover it" when the question
needs a folder outside the scope above. A good answer may be filed back as an `answer` page:
`## [<timestamp>] file-back | qa-<slug> | <question>`.

**Lint**: report contradictions between pages or sources, superseded or future rules stated as current, orphan
pages, broken links, uncited claims, and citations whose quote is not found at the cited location; fix them or
list them. Log: `## [<timestamp>] lint | <n> findings`.

## 9. index.md and log.md

`index.md` is the catalogue every query reads first: one line per staff page, grouped by type,
`- [[slug]] Title: summary`, rebuilt after every ingest. `restricted/index.md` is the same for HR pages.
`log.md` is append-only, oldest first: one line per ingest, file-back and lint, so the wiki's history can be
replayed.
